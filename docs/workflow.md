# AI 工程师调用与项目推进流程

## 当前基线

`data-v1` 已冻结并通过 D0-D5 验收。后续不重复生成 D2-D4，不再设置独立 A0；训练前数据契约检查已并入 A1。

项目由用户指挥，总负责人派工、验收和提交，数据、算法、应用三位 AI 工程师只修改各自范围。数据工程师进入维护状态，只有数据契约确实变化时才重新调用。

## 剩余阶段

| 阶段 | 负责人 | 实质交付 | 通过后进入 |
|---|---|---|---|
| A1 | 算法 | preflight、Dataset、预处理、ResNet-50 冒烟、小样本过拟合 | A2 |

`P1` 可与 `A1-A2` 并行；`P2` 必须等待 `A3`。工程师不得自行进入下一阶段。

## 派工格式

```text
执行 <阶段 ID>。只做该阶段，不自行提交或推送。
先读 docs/acceptance-checklist.md、对应职责与工作日志。
完成定向测试并按 7 行模板汇报，然后停止等待验收。
```

## 工程师汇报格式

```text
阶段：
修改文件：
运行命令：
测试结果：
关键指标：
遗留问题：
是否进入下一阶段：否
```

工作日志只追加这份摘要，不粘贴长控制台输出。普通任务运行定向测试和 `git diff --check`；仅 A1、A3、P2、F0 运行全量测试。模型训练只报告配置、时长、峰值显存和关键指标，不重复扫描冻结数据。

## 验收与提交

总负责人检查改动范围、定向测试、关键输出和 Git diff，结论只使用“通过”“退回”“阻塞”。退回时直接修复同一阶段，不建立新的阶段编号或专门提交退回日志。里程碑通过后由总负责人提交；除非用户明确要求，否则不推送。

原图、taxonomy、split 和冻结模型包不得原地修改。测试集只在 A3 方案冻结后评估一次。
