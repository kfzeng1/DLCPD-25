# DLCPD-25 分类系统开发计划

## 目标与边界

在剩余周期内交付一个可训练、可评估、可演示的 203 类图像分类系统。用户上传一张图片后，系统输出具体类别，并通过 taxonomy 映射出宿主作物和四大标签属性，同时显示置信度与 Top-5。

本项目不是目标检测：数据没有边界框或分割标注，系统不承诺定位虫体或病斑。

## 已有基础

- `data-v1` 已完成 D0-D5，含 203 类、221,377 张可用图片和固定 train/val/test。
- 三个 split 为 177,021 / 22,178 / 22,178，路径与 duplicate group 泄漏均为 0。
- 本机为 RTX 4070 Laptop，实际可用显存约 7.62 GiB；复用 `/home/zkf/pytorch-env`。
- 训练标签是 203 个细类；22 个宿主和四大类由 taxonomy 映射，不单独训练三个互相冲突的分类头。

## 模型路线

默认使用 ImageNet 预训练 `ResNet-50`、224 x 224 输入、AMP 和 batch size 16；显存不足时依次降到 8、4，再使用梯度累积。先打通训练与发布链路，再比较普通 CE 和一种类别不平衡策略。

`ConvNeXt-Tiny` 只在时间、显存和基线结果允许时做对照，不强制完整训练双模型。MAE、SimCLR v2 和 MoCo v3 不纳入当前交付。

## 剩余进度

| 建议时间 | 阶段 | 结果 |
|---|---|---|
| 第 1-2 天 | A1，同时启动 P1 | 训练链路、小样本过拟合、应用骨架 |
| 第 3-8 天 | A2，继续 P1 | 完整训练和验证对照；假模型页面完成 |
| 第 9-10 天 | A3 | 一次最终测试、模型包和错误分析 |
| 第 11-13 天 | P2 | 真模型集成、异常路径和演示 |
| 第 14 天 | F0 | 全量回归、文档、打包和答辩检查 |

剩余时间作为训练失败、OOM、依赖安装和效果不佳的缓冲。若进度落后，优先保留 ResNet-50、完整评估和可运行应用，取消可选模型对照与装饰性功能。

## 交付标准

最终应包含：可复现训练配置、最佳 checkpoint、Top-1/Top-5、Macro-F1、Balanced Accuracy、混淆矩阵、错误案例、版本化模型包、图片推理应用和启动说明。低置信度或域外图片必须显示不确定提示。

阶段顺序和汇报格式见 `workflow.md`，逐项标准见 `acceptance-checklist.md`。
