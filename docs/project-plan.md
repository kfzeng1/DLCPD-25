# 双数据集联合模型开发计划

## 最终目标

课题名称为“基于DLCPD-25数据集的农产品病虫害与缺陷分类目标检测系统”。最终只发布一个联合模型和一个 checkpoint：

```text
一张RGB图片
  -> 直接缩放为224x224并归一化
  -> 一个共享ResNet-50主干（一次前向）
      ├── 203类整图分类头
      └── FPN + RPN + Faster R-CNN检测头
          └── 96类IP102害虫框
```

分类与检测必须使用同一输入张量和同一主干特征。检测内部标签为 `1-96`，`0` 为背景；所有外部结果统一使用 DLCPD-25 `class_id 0-202`。没有 IP102 边界框的病害、健康和缺陷只能分类，不能定位。

## 已完成基础

- DLCPD-25 分类数据已冻结：203 类，train/val/test 为 `177,021/22,178/22,178`。
- 历史 ResNet-50 分类模型已完成，Test Top-1 `88.5517%`，可作为联合模型初始化权重。
- IP102 T0 已通过：train/val/test 为 `12,142/3,036/3,798`，有效框 `22,283`，97 个源标签映射为 96 个检测类。
- 类别映射、检测 Dataset 和共享模型骨架已存在。

历史分类模型使用 `resize 256 + center crop 224`，而联合模型固定为直接缩放 `224 x 224`。J1 已完成统一预处理适配，并冻结为 J3 的分类初始化 checkpoint。历史分类模型只作为上游初始化和对照，最终应用不再部署它。

## 交替训练

J2-J3 每个训练周期交替执行两类 step：

```text
DLCPD-25分类batch -> 分类交叉熵 -> 更新共享主干和203类分类头
IP102检测batch    -> 检测损失   -> 更新共享主干和检测分支
```

初始采用 `1:1` step 比例，不按两个数据集图片总量直接混合。分类 step 不更新检测头；检测 step 不更新分类头，但两类 step 都允许小学习率更新共享主干。这样既学习检测特征，也持续复习分类任务，降低灾难性遗忘。

## 训练选择规则

- J1 从历史分类 `best.pt` 初始化，不从 ImageNet 重新训练完整 25 epoch；只用 DLCPD-25 train/val 适配直缩 224。
- J2 先用小规模两个数据集证明交替梯度、单次共享前向和 checkpoint 恢复正确。
- J3 正式训练 10 轮，只根据 val 选模型：先要求分类 val Top-1 相对 J1 下降不超过 2 个百分点，再在合格 checkpoint 中选择检测 `mAP@0.5:0.95` 最高者。
- J4 前冻结权重、预处理、阈值和 NMS。两个 test 只用于最终报告，不反向调参。
- 最终模型包只含一个联合 checkpoint，不部署旧分类权重或单独检测权重。

## 硬件与取舍

本机为 RTX 4070 Laptop，可用显存约 7.62 GiB，使用 `/home/zkf/pytorch-env`。固定 `224 x 224` 可明显降低显存和训练时间，适合课程周期；代价是 IP102 小目标检测精度可能低于 640 输入。本项目接受该取舍，并通过逐类 AP 和小目标错误分析如实报告，不再切换第二套分辨率。

## 完成标准

- 一张 `224 x 224` 输入、一个共享主干、一次前向、一个联合 checkpoint；
- 203 类分类和 96 类害虫检测都可用；
- 两个训练数据集交替参与 J2-J3，共享主干不会只受检测数据驱动；
- 分类报告 Top-1、Top-5、Macro-F1、Balanced Accuracy；检测报告 mAP、AP50、Precision、Recall 和逐类 AP；
- 页面同时显示整图分类与害虫检测框，并明确检测范围；
- 原始数据、冻结 split、taxonomy 和模型大文件不进入 Git。
