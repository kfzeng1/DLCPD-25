# 基于 DLCPD-25 的农产品病虫害与缺陷分类目标检测系统：20 天 MVP

> 项目周期：20 天<br>
> 数据版本：本地 203 类、221,396 张图像，与官方 203 个类别一一对应<br>
> 最终目标：交付可演示、可评估、表述诚实的“全类别分类 + 部分类别定位 + Web/API”系统

## 1. 范围冻结

DLCPD-25 只有图像级分类标签，没有检测框。因此 20 天内不能训练一个可信的 203 类目标检测器。可交付范围固定为两条链路：

1. **203 类分类**：所有类别都能输出类别、中文显示名、置信度和 Top-5 结果。
2. **目标检测/定位**：只覆盖人工标注过的可见害虫或局部病斑类别；输出框、类别和置信度。

这里的“缺陷”仅指数据集中已有的病斑、生理障碍和健康异常，不包括尺寸、成熟度、碰伤、腐烂等级等 DLCPD-25 没有标注的商品质量缺陷。

### 20 天内明确不做

- 不给 203 个类别伪造整图检测框；
- 不做 1600 epoch 自监督预训练；
- 不同时比较大量检测器；
- 不承诺所有病害都有准确定位；
- 不做 TensorRT、多端适配、主动学习平台和完整 MLOps；
- 不把 Grad-CAM 热力图写成目标检测框指标。

## 2. MVP 功能

单图上传后返回：

```json
{
  "classification": {
    "class_id": 95,
    "official_name": "Myzus persicae(tomato)",
    "display_name": "Myzus persicae 桃蚜(番茄)",
    "score": 0.91,
    "top5": []
  },
  "detections": [
    {
      "bbox": [120, 86, 244, 218],
      "class_name": "Myzus persicae(tomato)",
      "score": 0.84
    }
  ],
  "localization_status": "detected|unsupported|no_target",
  "model_version": "mvp-1"
}
```

界面至少包含图片上传、原图/检测结果切换、Top-5 分类结果、置信度、类别名称和“不支持定位”的明确状态。

## 3. 系统架构

```text
图片上传
   |
   +-- 基础校验：格式、尺寸、RGB/EXIF
   |
   +-- 203 类分类器
   |      +-- Top-1 / Top-5 / 置信度
   |      +-- 低置信度 -> unknown/请人工复核
   |
   +-- 分类结果是否属于检测支持集？
          +-- 是 -> YOLO 检测 -> 框 + 分数
          +-- 否 -> localization_status=unsupported
   |
   +-- FastAPI -> Web 页面
```

分类是系统主能力，检测是有明确支持范围的增强能力。不要在接口中把 `unsupported` 显示成“未发现病虫害”。

## 4. 数据方案

### 4.1 分类数据

- 使用全部 203 类本地子集；
- 从 `research/class_map.json` 固定类别 ID 和显示名；
- 先计算 SHA-256，精确重复图片必须在同一个 split；
- 按类别分层划分 `train/val/test = 80/10/10`；
- 尾部类不足 20 张时采用最小可行划分，并在报告中标为 few-shot；
- 训练增强只作用于训练集。

首版分类模型选择 ImageNet 预训练的 `ConvNeXt-Tiny` 或 `EfficientNet-B0`，只选一个主模型。时间和显存紧张时优先 EfficientNet-B0；有 16 GB 以上 GPU 时优先 ConvNeXt-Tiny。

### 4.2 检测数据

检测支持集必须在第 1 天冻结：

- 单人项目：5–10 个目标清晰类别、800–1500 张图；
- 有 2–3 名标注人员：10–20 类、2000–3000 张图；
- 优先选择图片中确实能看见害虫个体、类别样本较充足、边界明确的类别；
- 健康类不画框，作为负样本；
- `garlic pest and diseases` 等混合类别不进入检测训练；
- 弥散病害优先留在分类链路；只有边界明确的病斑才进入检测集。

标注使用 CVAT 或 Label Studio，主格式保存为 COCO JSON，再转换为 YOLO。预标注工具只能提供候选框，最终框必须人工确认。

### 4.3 标框规则

| 场景 | 标注规则 |
| --- | --- |
| 单只清晰害虫 | 每只单独框 |
| 多只可区分害虫 | 全部实例分别框选 |
| 密集且不可区分 | 标 `group` 或排除，规则全库统一 |
| 清晰局部病斑 | 框住连续病斑区域 |
| 弥散症状/整叶变色 | 暂不做框，保留分类标签 |
| 健康图 | 零框负样本 |
| 目标不可见、只见受害结果 | 不伪造害虫框 |

检测模型只训练一个轻量 YOLO 基线。不要在 20 天内同时引入 RT-DETR 和实例分割模型。

## 6. 技术选型

| 模块 | 推荐选择 | 原因 |
| --- | --- | --- |
| 深度学习 | PyTorch + torchvision/timm | 分类生态成熟 |
| 分类器 | EfficientNet-B0 或 ConvNeXt-Tiny | 训练和部署成本可控 |
| 检测器 | Ultralytics YOLO small 级模型 | 标注、训练、导出链路短 |
| 标注 | CVAT | 框标注、审阅和 COCO 导出成熟 |
| API | FastAPI | 推理接口简单、自动生成文档 |
| Web | 轻量 HTML/JS 或现有前端框架 | 20 天内优先完成真实工作流 |
| 导出 | ONNX（有余量再做） | 不是 MVP 阻塞项 |

## 7. 验收标准

### 分类

- 203 个类别全部可输出；
- 报告 Top-1、Top-5、macro F1 和每类召回率；
- 测试集与训练集无精确重复泄漏；
- 输出低置信度拒识状态；
- 长尾类别单独报告，不用总体准确率掩盖。

### 检测

- 只评价人工标注的支持类别；
- 报告 `mAP50`、`mAP50:95`、Precision、Recall；
- 测试图完整标注，不能把漏标目标当背景；
- UI 明确列出检测支持范围；
- 健康负样本和困难背景纳入误报测试。

### 系统

- 单图上传可以完成分类并按支持范围执行检测；
- 返回官方名称、本地显示名、分数、模型版本和处理时间；
- 错误文件、超大图片、无检测支持类别都有明确提示；
- README 可以在一台新机器上复现安装和运行；
- 演示结果与实验报告使用同一模型权重。

## 8. 风险和取舍

| 风险 | 20 天处理方式 |
| --- | --- |
| 没有框标注 | 缩小检测类别，同时立即开始人工标注 |
| 203 类长尾严重 | 加权采样/损失，单独报告尾部类 |
| 类别名称不规范 | 对外保留官方名称，中文只作显示别名 |
| 病斑难以框定 | 留在分类链路，不能强行检测 |
| 重复图片导致虚高 | SHA-256 分组后切分 |
| 标注进度落后 | 优先减少检测类别，不降低标注质量 |
| GPU 时间不足 | 使用预训练轻量模型，限制调参轮数 |

## 9. 立即执行

1. 确认项目是单人还是有标注协作者，并按人数冻结检测类别上限。
2. 准备一台可训练 GPU，记录显存、CUDA 和 PyTorch 版本。
3. D1 就开始检测标注，不等分类器训练结束。
4. 先完成 manifest、重复分组和 split，再训练分类器。
5. D8、D12 分别冻结分类和检测模型；后续只修系统集成问题。

最关键的取舍是：**203 类全部做分类，少量高质量类别做真正的目标检测**。这是 20 天内既能交付系统、又不制造虚假检测标签的方案。
