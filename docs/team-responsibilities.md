# 三位 AI 工程师职责与协作

## 总负责人（项目负责人）

我作为总负责人负责范围控制、技术决策、每日验收和最终交付。具体职责是冻结数据和类别口径，确认算法实验是否值得投入，处理三位工程师之间的接口冲突，审核指标和演示结果，维护总 README、开发文档和最终 Git 版本。

总负责人不替代三位工程师写全部代码，而是以交付物和验收标准管理工作。

## AI 数据工程师

### 负责范围

负责 `data/`、`metadata/`、`scripts/` 中的数据相关工作。

### 必须完成

- 审计 203 个官方类别和 221,396 张本地图片；
- 维护 `class-taxonomy.json`，保证宿主、四大类、细类映射唯一；
- 计算 SHA-256、dHash，识别精确和近重复图片；
- 先按重复组再生成分层 train/val/test；
- 生成每类数量、宿主数量、长尾和坏图报告；
- 输出算法工程师可直接读取的 CSV/JSON split；
- 给出数据版本号、生成配置和校验和。

### 不负责

不选择模型、不修改类别含义、不把目录名改成检测标注、不复制原图。

### 交接标准

算法工程师拿到 split 后，可以只依赖相对路径和 class ID 完成训练；重新运行数据脚本能够得到相同的 manifest 和 split。

## AI 算法工程师

### 负责范围

负责 `project/src/` 的训练、评估、模型和实验产物。

### 必须完成

- 复用并验证 `/home/zkf/pytorch-env`，补齐项目依赖但不重装 PyTorch；
- 实现 ImageNet 预训练 ResNet-50 基线；
- 实现 ImageNet 预训练 ConvNeXt-Tiny 主模型；
- 比较普通交叉熵、加权交叉熵和一种采样策略；
- 保存最佳权重、训练日志、配置和随机种子；
- 输出 Accuracy、Top-5、Macro-F1、Balanced Accuracy、混淆矩阵；
- 按宿主和四大类分析结果；
- 记录至少 30 个错误案例和改进建议；
- 主线完成后，才考虑 MAE、SimCLR v2 或 MoCo v3 的小规模扩展。

### 不负责

不修改原图、不重新定义 203 类、不直接开发前端、不把 Grad-CAM 当作目标检测结果。

### 交接标准

应用工程师拿到一个固定模型目录、类别映射和推理 API；在同一图片上能得到稳定的 class ID 和置信度。

## AI 应用工程师

### 负责范围

负责 `project/src/` 的推理封装、Web 页面、异常处理和演示材料。

### 必须完成

- 实现模型加载和 CPU/CUDA 自动选择；
- 将 203 类预测映射为宿主、四大类和详细类别；
- 实现图片上传、预览、Top-5 和低置信度提示；
- 处理损坏图片、非 RGB、超大图片和模型缺失；
- 显示模型版本、数据版本和推理时间；
- 编写本地启动说明和端到端冒烟测试；
- 生成答辩截图和 3–5 个演示样例。

### 不负责

不修改训练标签、不在页面中伪造边界框、不直接调参替代算法工程师实验。

### 交接标准

用户从浏览器上传图片即可得到三级一致结果；错误输入会显示可理解的提示而不是堆栈信息。

## 协作顺序

```text
数据工程师冻结 v1
        ↓
算法工程师训练 baseline / ConvNeXt
        ↓
应用工程师接入最佳权重
        ↓
总负责人联调、验收、写报告和提交
```

每日同步四项数字：数据版本、训练版本、Macro-F1、当前阻塞项。任何类别映射变更都必须先通知总负责人并生成新版本，不能静默覆盖。
