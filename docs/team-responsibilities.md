# 三位 AI 工程师职责

## 总负责人

总负责人维护阶段、接口和 Git 边界，统一派工、复验、提交和总结。每次只授权一个明确阶段；工程师不得自行进入下一阶段、提交或推送。用户决定是否启动下一阶段及是否推送远端。

## 数据工程师

负责 T0，所有权范围为 IP102 数据审计与转换、检测 split、数据合同、`detection/dataset.py`、对应脚本和测试。

必须完成：

- 核对 18,981 张检测图片、18,976 个 XML 和 18,976 个官方划分 ID；
- 兼容官方重复根 XML `IP087000986.xml`，保留原文件不改；
- 过滤 `IP046000898.xml` 中唯一零宽框并记录，保留同图有效框与原 XML；
- 排除官方划分外 5 张图片，记录原始 22,284 框与有效 22,283 框；
- 使用官方 `trainval` 生成一次固定 train/val，保留官方 test；
- 保持图片级隔离，统计每类图片数、框数、框尺寸和长尾情况；
- 固定 `metadata/ip102-detection-class-map.json` 的 97 源标签到 96 个 DLCPD-25 类别映射；
- 输出轻量、可复验的数据合同，禁止重新做无必要的全量感知哈希流程。

官方检测 test 缺少 IP102 源类别 61，最终评估必须将其标记为无 test 支持，不能伪造该类 AP。

禁止删除或改写原始图片/XML，禁止改动 DLCPD-25 冻结 split、taxonomy 和分类模型包，禁止把官方检测 test 用作验证集。

## 算法工程师

负责 T1-T3，所有权范围为 `detection/model.py`、检测训练与评估代码、检测配置、算法测试及检测训练/发布 artifacts。

T1：加载现有 203 类 `best.pt`，验证共享 ResNet-50 权重、96 类检测头、AMP、checkpoint 重载、单批过拟合与显存。

T2：先冻结主干训练检测分支，再根据验证结果决定是否只解冻 `layer4`；只使用 T0 train/val 选择 checkpoint，记录训练时长、峰值显存和检测指标。

T3：冻结模型、预处理和阈值后仅执行一次官方检测 test；输出 mAP@0.5、mAP@0.5:0.95、Precision、Recall、逐类 AP、长尾分析、错误案例和完整模型包。

禁止重新训练或覆盖现有 203 类分类模型；禁止使用检测 test 调参；禁止把内部 `1-96` 标签暴露为公共类别 ID；禁止宣称能检测没有 IP102 框标注的病害和缺陷。

## 应用工程师

负责 T4，所有权范围为 `inference/`、`web/`、应用配置、应用测试和运行文档。

必须完成：

- 在同一上传流程中运行整图分类和害虫检测；
- 以 DLCPD-25 `class_id 0-202` 展示两种结果；
- 绘制检测框、类别名和置信度，支持无框、多框与低置信度；
- 加载前验证分类和检测模型包，不复制训练预处理逻辑；
- 保持损坏图、超大图、CPU/CUDA 回退和模型缺失错误处理；
- 页面明确“分类覆盖203类，目标检测只覆盖IP102有框的96类害虫”。

禁止修改训练数据、类别映射、split 或权重，禁止伪造病斑/缺陷检测框，禁止将整图 Grad-CAM 当作检测框。

## 交接顺序

```text
现有分类基线 ──────────────────────────────┐
IP102原始检测数据 -> T0 -> T1 -> T2 -> T3 -> T4 -> F1
共享203类taxonomy与映射 ────────────────────┘
```

工程师交付只写简短工作日志：阶段、修改文件、命令、测试、指标、遗留问题、是否进入下一阶段。长控制台输出不写入文档。
