# 三位 AI 工程师职责与阶段任务

## 1. 项目指挥者与总负责人

用户是项目指挥者，负责决定何时调用哪位 AI 工程师、是否接受范围或目标变更，以及何时提交和推送。用户不需要亲自判断工程产物是否合格，可先要求总负责人验收，再决定是否进入下一阶段。

当前助手是总负责人，负责：

- 维护任务顺序、范围、接口和验收标准；
- 派工前检查前置版本，避免无效开发；
- 工程师交付后独立重跑测试并检查 Git diff；
- 发现越权修改、数据泄漏、指标失真或接口不一致时退回；
- 每阶段向用户总结状态、风险和下一步建议；
- 统一管理文档、版本、最终集成、Git 提交和答辩材料。

总负责人不得仅凭工程师自述判定通过，也不得在前置条件失败时安排下游继续开发。

## 2. AI 数据工程师

### 负责和禁止范围

负责 `scripts/` 的数据脚本、`metadata/` 的已批准元数据、`project/src/dlcpd25_classifier/data/`、数据测试和 `artifacts/data/` 产物。

禁止删除、移动、重命名或覆盖 `data/raw/`；禁止使用 `data/views/` 训练；禁止静默修改 class ID 或类别语义；禁止让重复组跨 split；禁止训练模型、开发页面、升级 PyTorch 或擅自执行下一阶段。

### 阶段任务

| 阶段 | 工作 | 必须交付 | 通过条件 |
|---|---|---|---|
| D0 | 冻结数据根、203 类与 taxonomy | 版本配置、统计、校验和 | 203 类、221,396 文件、ID 0-202、映射唯一 |
| D1 | 建 manifest、解码和坏图审计 | manifest、坏图表、摘要、脚本和测试 | 相对路径唯一、统计一致、坏图不被擅删 |
| D2 | 计算 SHA-256、dHash 和重复组 | 带哈希的 manifest、重复报告 | 完全重复同组、阈值可追溯、有抽查证据 |
| D3 | 按重复组分层切分 | train/val/test CSV、配置和统计 | 路径互斥、重复组跨 split 为 0 |
| D4 | 验证复现与加载 | 复现测试、校验和、加载冒烟结果 | 两次运行结果一致、三个 split 可加载 |
| D5 | 冻结 data-v1 | `data-handoff-v1.md` 和版本清单 | 风险、数量、命令和所有 SHA-256 完整 |

交接后，算法工程师只需读取相对路径、split、固定 class ID 和 taxonomy，不应重新扫描目录或推断标签。

## 3. AI 算法工程师

### 负责和禁止范围

负责 `project/src/dlcpd25_classifier/models/`、`training/`、算法使用的推理核心、相关测试，以及 `artifacts/training/` 和 `artifacts/releases/` 模型产物。

禁止修改原图、split 和 taxonomy；禁止用 test 调参；禁止覆盖旧 run；禁止另写与应用方不一致的预处理；禁止把 Grad-CAM 称为检测结果；主线未完成前不投入 MAE、SimCLR v2 或 MoCo v3。

### 阶段任务

| 阶段 | 工作 | 必须交付 | 通过条件 |
|---|---|---|---|
| A0 | data-v1 准入 | 自动检查和准入报告 | 类别、hash、路径、split、重复组全部通过 |
| A1 | 训练链路冒烟 | Dataset、transform、model、CLI、checkpoint 测试 | `[N,203]`、无 NaN、可重载、小样本明显过拟合 |
| A2 | ResNet-50 基线 | 完整 run、日志、val 指标 | 固定 seed/split，CPU/CUDA 可评估，不看 test 选型 |
| A3 | ConvNeXt-Tiny 和不均衡对照 | 单变量实验及资源记录 | 用 val Macro-F1 主选，时长/显存可追溯 |
| A4 | 冻结选择和最终测试 | 全部指标、混淆矩阵、30 个错误案例 | 先冻结后只测一次 test，无泄漏或测试集调参 |
| A5 | 模型交接 | 版本化模型包、模型卡、参考推理结果 | 权重、配置、预处理、taxonomy 和校验和齐全 |

如果 ConvNeXt-Tiny 没有优于 ResNet-50，算法工程师必须如实报告，可选择 ResNet-50 发布，不得为符合预设结论隐瞒结果。

## 4. AI 应用工程师

### 负责和禁止范围

负责 `project/src/dlcpd25_classifier/inference/`、`web/`、应用配置、应用测试和演示材料。应用工程师负责加载、校验、异常处理和展示，不负责重新定义模型预处理或修改权重。

禁止修改训练标签、原图和模型；禁止自行调整冻结阈值；禁止伪造检测框；禁止对低置信度或域外图片给出确定诊断；禁止在真实模型包未验收前宣称系统完成。

### 阶段任务

| 阶段 | 工作 | 必须交付 | 通过条件 |
|---|---|---|---|
| P0 | 冻结推理与模型包契约 | schema、接口说明和契约测试 | 203 类顺序、预处理、输出字段和版本均明确 |
| P1 | 假模型推理内核 | Predictor、图片处理、Top-k 和单测 | 灰度/RGBA/EXIF 可处理，错误无未捕获堆栈 |
| P2 | 假模型 Web 应用 | Gradio 页面、启动命令和 UI 冒烟 | 三级结果、Top-5、低置信度、版本和耗时齐全 |
| P3 | 接入 A5 模型包 | 集成测试、固定参考 JSON、性能记录 | 校验和全部匹配，算法 CLI 与应用结果一致 |
| P4 | 发布和演示 | 3-5 个样例、截图、启动与排错说明 | 根目录可启动，全量测试通过，异常路径可演示 |

P0-P2 可在算法训练期间使用固定假 logits 开发。P3 必须等待 A5，不允许应用工程师为适配页面直接修改模型包。

## 5. 交接与冲突处理

```text
D0 -> P0 -> P1 -> P2 --------------------┐
D0 -> D1 -> D2 -> D3 -> D4 -> D5         |
                              -> A0 -> A1 -> A2 -> A3 -> A4 -> A5
                                                        |       |
                                                        └-> P3 -> P4 -> F0
```

- 数据与算法冲突：以 data-v1 和 taxonomy 校验和为准，算法不得现场改标签。
- 算法与应用冲突：以 A5 模型包 manifest 和 P0 接口契约为准，任何修改生成新版本。
- 文档与代码冲突：以实测代码为事实，先修正实现或文档，再通过验收。
- 用户已有改动与工程师任务冲突：工程师停止相关文件修改，由总负责人协调。

## 6. 工程师汇报要求

每位工程师使用 `workflow.md` 的阶段完成报告模板，并明确列出 `git status`。实施过程必须追加到自己的 `worklogs/` 文件；日志缺失视为交付不完整。

三位工程师均没有验收权，不能修改 `project-lead.md` 或 `acceptance-checklist.md` 中的状态，也不能自行提交或推送。用户和总负责人可根据 `prompts/` 中的固定提示词恢复新的工程师会话，新的工程师必须先阅读历史日志，再继续指定阶段。
