# 工作日志规则

本目录用于跨会话保存项目上下文。稳定规则写入上级文档，详细运行产物写入 `artifacts/`；工作日志只记录可追溯摘要、路径和校验和。

## 文件所有权

| 文件 | 唯一维护者 | 内容 |
|---|---|---|
| `data-engineer.md` | AI 数据工程师 | D0-D5 实施记录 |
| `algorithm-engineer.md` | AI 算法工程师 | A0-A5 实施记录 |
| `application-engineer.md` | AI 应用工程师 | P0-P4 实施记录 |
| `project-lead.md` | 总负责人 | 验收、退回、决策和项目总结 |

工程师只能追加自己的日志。三位工程师都不能修改 `project-lead.md` 或 `../acceptance-checklist.md`；这两个文件只由总负责人在独立复验后更新。

## 记录时机

- 开始阶段时追加“进行中”记录，注明前置版本和本次范围。
- 完成或受阻时补齐同一条记录，状态改为“待验收”或“阻塞”。
- 总负责人验收后，在 `project-lead.md` 追加结论并更新验收清单。
- 返工仍使用同一阶段 ID，但增加修订序号，例如 `D2-R1`。

## 工程师记录模板

```markdown
## YYYY-MM-DD <阶段 ID> <简短标题>

- 状态：进行中 / 待验收 / 阻塞
- 指挥者指令：
- 前置版本：Git commit、数据、模型、taxonomy
- 允许范围：
- 实际修改：
- 生成产物：路径、版本、SHA-256
- 执行命令：命令、退出码、关键输出
- 验收证据：逐项对应阶段标准
- 关键统计：
- 偏差、风险和阻塞：
- Git 状态：
- 下一步建议：
- 边界声明：未执行下一阶段
```

## 总负责人记录模板

```markdown
## YYYY-MM-DD <阶段 ID> 验收

- 结论：通过 / 退回 / 阻塞
- 验收输入：
- 独立复验命令与结果：
- 文件和范围检查：
- 关键证据：
- 发现的问题：
- 验收清单更新：
- 建议下一阶段：
- 用户决定：待确认 / 已批准 / 暂停
```

日志不保存大段控制台输出、完整 CSV、模型权重或图片。此类内容放入版本化 `artifacts/` 目录，日志仅引用路径和摘要。
